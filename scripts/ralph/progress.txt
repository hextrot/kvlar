# Ralph Progress Log — Kvlar
Started: 2026-03-04

## Codebase Patterns
- kvlar-core must remain pure (no I/O, no async) — ADR-003
- Fail-closed default: deny if no rule matches
- Publish crates in dependency order: kvlar-audit, kvlar-core, kvlar-proxy, kvlar-cli
- Binary name is 'kvlar' (not kvlar-cli), set via [[bin]] in Cargo.toml
- MCP denials use tool results with isError:true (not JSON-RPC errors)
- All proxy watcher/reload messages go to stderr (stdio safety)
- Rust 2024 edition, Apache 2.0 license
- Arc<RwLock<Engine>> for concurrent policy evaluation with exclusive hot-reload writes
- notify crate v7 for filesystem watching (FSEvents on macOS, inotify on Linux)
- 300ms debounce on file watcher to coalesce rapid editor saves
- ExtendsResolver type: Arc<dyn Fn(&str) -> Result<String, KvlarError> + Send + Sync>

## 2026-03-04 — US-007: Graceful shutdown and signal handling
- Created kvlar-proxy/src/shutdown.rs with CancellationToken-based signal handling
- signal_shutdown_token() listens for SIGTERM/SIGINT (Unix) or Ctrl+C (Windows)
- Logs "shutting down..." on signal receipt
- StdioTransport::run() uses tokio::select! to race proxy loop vs shutdown signal
- McpProxy::run() uses tokio::select! in accept loop, breaks on shutdown
- Both transports flush audit log and clean up child processes on shutdown
- Added AuditLogger::flush() method for explicit file sink flushing
- Added tokio-util to workspace deps for CancellationToken
- 3 new tests (token manual, child tokens, shutdown timeout), 112 total
- Files: shutdown.rs, stdio.rs, proxy.rs, lib.rs, logger.rs, Cargo.toml (workspace + proxy)
- **Learnings:**
  - tokio-util CancellationToken is lightweight — no Arc needed, clone is cheap
  - tokio::select! is the right pattern for "run until signal or completion"
  - AuditSink::File uses std::fs::File which buffers — flush() ensures persistence
  - Unix signals need separate signal() listeners for SIGTERM and SIGINT
